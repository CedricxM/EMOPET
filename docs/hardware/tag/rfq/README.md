# TAG external-test RFQ response workflow

**Issue:** #580

## Files

- `TAG_PHASE0_EXTERNAL_TEST_RFQ_2026-09-25.md` — technical RFQ.
- `TAG_FIXTURE_ENGINEERING_ENQUIRY_EMAIL_2026-09-25.txt` — concise first-contact email for fixture/bring-up candidates.
- `TAG_RF_EMC_LAB_ENQUIRY_EMAIL_2026-09-25.txt` — concise first-contact email for specialist labs.
- `TAG_EXTERNAL_TEST_VENDOR_MATRIX_2026-09-25.csv` — normalized response matrix.

## Response discipline

For every supplier reply:

1. attach/store the original email/quotation;
2. update only facts explicitly stated by the supplier;
3. preserve `TBD` where the reply is silent;
4. record quotation currency and whether tax/shipping are included;
5. separate website claims from written quotation commitments;
6. never mark accreditation as YES without the exact scope/certificate reference;
7. never infer IP/source handover from “custom fixture” language;
8. never infer production suitability from prototype capability;
9. never merge engineering/pre-compliance pricing with formal certification pricing.

## Selection gate

Do not rank or select until at least these fields are known for the applicable category:

- scope;
- deliverables;
- raw-data access;
- IP/source handover;
- price;
- lead time;
- re-test terms;
- sample logistics;
- accreditation scope where relevant.

MOKO remains the intended repeatable execution/manufacturing boundary unless a later decision changes that architecture.
