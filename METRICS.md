# EMOPET — Metrics

**Status:** `COMPANY OS METRIC PROJECTION / NOT DOMAIN AUTHORITY`  
**Machine-readable source:** `state/metrics/metrics.json`

EMOPET does not measure progress by PR count, commit count or feature count.

A metric belongs here only when it can inform a **decision, gate or learning loop**.

## Current metric families

### Physics

- MAT qualification rate — **DEFINED / NOT MEASURED**
- MAT repeatability — **DEFINED / NOT MEASURED**
- TAG physical-evidence coverage — **DEFINED / NOT MEASURED**

No numerical threshold is invented here. Controlled protocols/gates own thresholds where needed.

### Economics

- landed MAT+TAG bundle COGS — **DEFINED / NOT MEASURED**

Quotes are evidence inputs, not actual COGS.

### Product

- recurring owner value — **PROPOSED / NOT MEASURED**

The S2 instrument and threshold must be controlled before this becomes a gate metric.

### Trust

- ELI abstention/degradation rate — **DEFINED / NOT MEASURED**

This measures whether the system respects uncertainty. It is not a target to maximize or minimize blindly.

## Proof Velocity

**Proof Velocity** is deliberately not a magical startup score.

It means:

> the number of critical uncertainties that reach an evidence-backed GO, ITERATE, HOLD, REDIRECT or KILL disposition during a review period.

The underlying decisions must remain visible. A correct `KILL` can represent more progress than 50 merged features.

## Anti-vanity rule

`COMMITS != PROGRESS`  
`FEATURES != PRODUCT_VALUE`  
`DOWNLOADS != RETENTION`  
`ACCOUNTS != ACTIVATED_HOUSEHOLDS`  
`DASHBOARD_PERCENT != PHYSICAL_PROOF`
